Supervisor Agent — User Flow

Based on the routing rules in main.py (login gating, tool selection, anti-fabrication checks).

flowchart TD

Guest vs. logged-in access

ToolGuestLogged in (email)Why
faq_agent✅✅General FAQ — public content
shipping_refund_info_agent✅✅Return/exchange policy — general, not account-specific
order_agent🚫 → LOGIN_REQUIRED✅Caller's own order data
panda_agent🚫 → LOGIN_REQUIRED✅Pricing/catalog gated to logged-in callers

Login state travels as a one-time leading system message from the chat backend (guest vs. email + the real email address), which the supervisor's access-control middleware reads, restricts the tool list from, and then replaces with a plain-language note so the model knows the current caller's actual login state — not just that "some caller" might need one.
